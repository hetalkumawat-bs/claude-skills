# Diagrams

`.dot` sources are checked in beside the document; PNGs are derived and regenerated by the build.
Never hand-edit a PNG — the next build overwrites it, and the source is the thing a reviewer can
correct.

```bash
dot -Tpng -Gdpi=150 assets/architecture-highlevel.dot -o assets/architecture-highlevel.png
# or, for every .dot at once:
build-doc.sh doc.md --diagrams docs/assets
```

150 dpi is the sweet spot: crisp at 6.6in in Word without bloating the file.

## Which diagrams earn their page

Seven is a full set; four is common. A diagram that restates a table earns nothing.

| Diagram | Shows | Section |
| --- | --- | --- |
| High-level architecture | layers — presentation, application, data, external | 2.1 |
| Request / response flow | the numbered path from user to store and back | 2.4 |
| Deployment topology | cloud project → region → VPC → subnet, with real resource names | 9.1 |
| CI/CD | branch → build → deploy, per environment | 9.3 |
| Business context | actors → platform → outputs and external systems | 13 |
| Key user journey | the flagship flow, step by step | 14.3 |
| Data model | entities and relations | Appendix A |

## House style

Palette: the **client's** primary brand colour for structural nodes when the document is about
their product, otherwise BigStep blue `#1C62EC`. Below, `#263C8A` is the primary — swap it and its
two tints. Data stores get the deeper tint, external systems get the amber family, so a reader
can tell "ours" from "theirs" without the legend.

```dot
digraph Name {
  rankdir=TB; bgcolor="white"; compound=true; splines=polyline;
  nodesep=0.55; ranksep=0.85; fontname="Helvetica";

  node [shape=box, style="rounded,filled", fontname="Helvetica",
        fontsize=12, color="#263C8A", fillcolor="#EAF0FB",
        fontcolor="#1b2a5e", penwidth=1.4, margin="0.22,0.16",
        width=2.6, height=1.0, fixedsize=true];
  edge [fontname="Helvetica", fontsize=11, color="#5b6b8c",
        fontcolor="#3a4a6b", arrowsize=0.85, penwidth=1.2];
  graph [fontname="Helvetica-Bold", fontsize=15, fontcolor="#263C8A"];
}
```

Role colours:

| Role | fill | border |
| --- | --- | --- |
| Service (default) | `#EAF0FB` | `#263C8A` |
| Actor / entry point | `#263C8A` + white text | `#1b2a5e` |
| Data store | `#D7E3F7` | `#1b2a5e` |
| External / third-party | `#FBF1D6` | `#B07F1B` |
| Layer cluster | `#F3F7FE` | `#AFC0E4` |
| External cluster | `#FBF6E9` | `#D8B24A` |

Layers are clusters with `labeljust="l"` and a two-space label indent, `style="rounded,filled"`,
`margin=18`. Members of one layer sit on one row — `rank="same"` inside the cluster, or a
`{ rank=same; a; b; }` group outside it.

Rules that keep them readable:

- **`fixedsize=true` with a shared `width`** — uniform boxes are what make it look drawn rather
  than generated. Break labels with `\n`, three lines maximum: name, technology, port or host.
- **Twelve nodes is the ceiling.** Past that, split into two diagrams.
- **Label every edge with a verb or a step number** (`" 4a · content (REST)"`) — a leading space
  keeps the label off the line. Number the steps when the diagram tells a sequence.
- **Fix crossings with rank, not with hand-placed coordinates.**
- Ports and real resource names in the labels. `Cloud Run acme-frontend-prod` beats `Frontend`.

## Cloud topology

Nested cloud boundaries are clearer from the `diagrams` Python library, which draws real provider
icons, than from hand-written dot:

```bash
python3 -m venv /tmp/diagvenv && /tmp/diagvenv/bin/pip install diagrams   # needs graphviz
PATH="/opt/homebrew/bin:$PATH" /tmp/diagvenv/bin/python assets/generate_diagrams.py
```

Nest `Cluster`s to mirror the real hierarchy — project → region → VPC → subnet → zone — and put
external actors (users, DNS, third-party APIs) outside the project cluster. Every resource name in
the diagram comes from a live `gcloud`/`aws` listing, and the caption says when it was verified.

Keep the generator script next to the document in `assets/`, so the diagrams are reproducible by
whoever inherits it.
